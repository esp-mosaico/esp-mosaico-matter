# Cppcheck and development checks

Run these commands from the repository root. Use a separate Python 3.10+
environment for repository tooling:

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements-dev.txt
# Ubuntu/Debian; use your system package manager on other platforms:
sudo apt install cppcheck
pre-commit install
pre-commit run --all-files
```

The hooks check YAML/TOML syntax, merge markers, whitespace, Python errors
with Ruff, and C/C++ errors with cppcheck. Ruff uses its default error rules
without applying automatic fixes or enforcing a new formatting style. Its
version is shared by `requirements-dev.txt` and the hook revision; update both
together. The first hook run downloads its isolated Python environments.

Run the language checks separately with:

```sh
ruff check .
python3 tools/cppcheck/check_cppcheck.py
```

cppcheck 2.13+ scans production C/C++ sources under `components/`, separately
for each component. Changes to headers trigger a full component scan too.
Third-party code, downloaded dependencies, build output, and frontend bundles
are excluded. File-scoped suppressions in
[`.cppcheck-suppressions`](.cppcheck-suppressions) cover a reproduced cppcheck
2.13 parsing bug with `new (std::nothrow)` and ESP-IDF's per-directory `readdir`
storage. Missing cppcheck or any reported error fails the hook.

This quick scan supplies project headers, without ESP-IDF/CHIP configuration.
It does not cover every target-dependent branch or replace firmware builds.
For target-specific analysis, cppcheck also supports the
`compile_commands.json` generated by an ESP-IDF build via `--project`.
See the [cppcheck manual](https://cppcheck.sourceforge.io/manual.html),
[Ruff configuration](https://docs.astral.sh/ruff/configuration/), and
[pre-commit documentation](https://pre-commit.com/) for the tool options.
